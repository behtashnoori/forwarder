# PDR-017 — Canonical Operational Taxonomy

- **Status:** Accepted
- **Date:** 2026-08-03
- **Decision scope:** Vocabulary and conceptual boundaries only
- **Implementation authority:** Vocabulary only; Slice-specific authority remains required
- **Sources:** PP-001, AP-001, FDD-001, FDM-001, PDR-015, PDR-016, ADR-025, ADR-026, repository evidence at `46cfc2bd359ee28968e8bdde3ed1eebfda1b1f0f`

## Purpose and authority boundary

This record defines the shared vocabulary for Project configuration, execution, evidence, and later reporting. Acceptance is for terminology and boundaries only: it does not automatically authorize any present or future capability. Schema, API, UI, Seed, migration, deployment, and operational behavior require Slice-specific authority. “Implemented” below means repository implementation was observed; it does not mean Release 1.8.0 or Production deployment. Terms not evidenced by the repository remain `TBD — Governance Decision Required`; this record does not invent them.

## Required distinctions

1. Project configures reusable expectations; OperationalShipment records one execution.
2. ShipmentRequest records commercial intent; OperationalShipment records accepted operational execution.
3. ServiceType classifies offered outcomes; TransportMode classifies physical movement.
4. LogisticsPoint is reusable place master data; Checkpoint is an occurrence/plan element.
5. Checkpoint structures route control; Milestone identifies a time-sensitive expected/actual control fact.
6. Milestone is the operational control instance; OperationalEvent is append-only evidence about facts including milestone changes.
7. Activity is work over time; Event records that something occurred.
8. Status is current state; Event is historical evidence of occurrence/change.
9. Delay is lateness against a target; Exception is a deviation requiring management.
10. Document is a managed business file/record; Evidence is the role a fact or artifact plays in proving something.
11. SLA includes commitment and measurement governance; target duration is only a planning parameter.
12. CargoCatalogItem is reusable mutable master data; ShipmentCargoItem is historical transaction meaning.
13. Carrier performs carriage; Forwarder coordinates service and may subcontract it.
14. Project configuration has no hidden execution side effects; operational creation/snapshotting requires separate accepted authority.

## Decision

Adopt this vocabulary and the required distinctions. PDR-017 defines vocabulary and boundaries; it does not authorize future capabilities automatically. Implementation authority remains Slice-specific. Required approvers are role authorities: Product, Architecture, Operations, and Data, with Security consulted where visibility, party, evidence, or organization-isolation boundaries apply. No named individual signatures are asserted.
